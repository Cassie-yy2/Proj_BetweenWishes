心愿之间（Wish Between）产品需求文档

面向情侣的心愿分享与惊喜送礼闭环应用原型设计说明书

一、产品概述

1.1 产品名称

心愿之间（Wish Between）

1.2 产品定位

一款面向情侣的心愿分享与惊喜送礼应用。通过心愿清单帮助用户真诚、无负担地表达自己的喜好；通过随机抽选与保密机制帮助另一半在适当时刻完成充满惊喜感的送礼过程。

1.3 产品 Slogan

愿望悄悄许，惊喜自然来。

二、产品背景与用户痛点

在情侣恋爱与节日互动中，送礼通常存在以下核心问题：

角色 日常痛点 心理诉求
收礼方（被送礼人） • 不好意思直接开口要求特定礼物；
• 暗示容易被对方忽略或误解；
• 收到不对心意的礼物时既尴尬又浪费。 		希望另一半能送自己真正喜欢的礼物，同时不想显得功利，渴望保留仪式感。
送礼方（挑选礼物人） • 不清楚对方当下真正想要、缺少什么；
• 担心买错型号、尺寸或色号踩雷；
• 直接问会丧失神秘感，自行瞎猜又压力巨大。 		希望有一份明确的“灵感参考答案”，但送出时依然是一场未知惊喜。

因此设计「心愿之间」：让用户平时提前记录愿望，由另一半在合适的时候进行预算筛选、随机抽取与惊喜赠送。

三、产品目标

3.1 核心目标

建立情侣之间的「心愿表达 → 惊喜抽选 → 礼物完成」良性互动闭环：

1. 心愿表达 (平时记录)
→
2. 惊喜抽选 (节日/纪念日)
→
3. 保密履约 (线下下单)
→
4. 送出揭晓 (仪式感)
→
5. 历史珍藏 (共同回忆)

3.2 V1.0 验证目标 (MVP)

验证情侣用户是否愿意通过心愿清单降低送礼决策与沟通成本，同时通过随机抽选机制保留彼此期望的送礼惊喜感。

四、目标用户

核心用户：情侣用户。

  • 热恋中的情侣：互送礼物频率高，注重仪式感与惊喜感；
  • 异地恋情侣：无法经常线下见面，渴望通过心愿单寄托思念与精准送礼；
  • 纪念日/生日/节日有送礼需求的用户：渴望消除送礼焦虑，避开直男/直女审美误区。

五、V1.0 产品范围（MVP 必做功能 P0）

5.1 用户账号

支持基础账号能力，包括注册与登录、用户头像设置（预设萌趣头像 / 自定义链接）、昵称、唯一用户名（用于情侣邀请搜索）以及个性签名。

5.2 情侣唯一绑定

功能说明：情侣双方建立唯一关系，共同管理彼此的心愿与送礼空间。

A 发送情侣邀请 (账号搜索 / 链接)
→
B 接受确认
→
建立唯一情侣关系空间

核心业务规则：

  • 双向确认：必须接收方主动确认接受后才能建立绑定；未接受时不互通心愿；
  • 唯一性约束：一个账号在 V1.0 中只能绑定一个情侣对象，无法与多个人同时绑定；
  • 解除绑定机制：任一方均可单方面解除绑定。解除后立即终止双方之间所有未完成的抽选任务，对应已锁定的心愿立即解除锁定重回清单，并向对方发送站内解绑通知。

5.3 我的心愿清单

功能说明：用户创建并维护属于自己的礼物愿望。

字段 必填/选填 业务要求与说明
心愿名称 必填 心仪礼物标题，如“复古手冲咖啡壶”、“NuPhy 矮轴机械键盘”
商品图片 选填 最多支持 5 张商品参考图（支持快捷预设图与网络图片）
参考价格 选填 数字数值（元），用于送礼方的最高预算筛选匹配
商品链接 选填 淘宝/京东/天猫/得物等平台商品网页链接
规格参数 选填 如颜色、尺码、型号、容量（如“燕麦米色 / M码”）
优先级 必选 分为 🔥高 / ✨中 / 🌱低（直接影响抽选算法命中概率）
心愿备注 选填 个人喜好补充说明、期许理由或使用场景
期望截止日期 选填 到期后该心愿自动暂停参与新的送礼抽选

心愿展示与排序：

  • 多视图切换：支持高颜值「卡片网格模式」与紧凑高密度的「列表模式」自由切换；
  • 排序方式：默认按照添加时间倒序，支持分类与优先级筛选；
  • 清单暂停：支持一键暂停清单参与抽选；暂停后不影响已锁定的送礼任务。

5.4 心愿可见权限

V1.0 极致简化：

  • 双方完成情侣绑定后，默认互相可查看彼此的心愿清单；
  • 在「心愿」页面顶部提供分段切换器：【我的心愿】 ⇋ 【TA的心愿】；
  • V1.0 暂不包含复杂的分组权限、公开分享链接与多人授权。

5.5 随机抽选送礼（核心惊喜机制）

功能说明：情侣一方可以从另一方的心愿清单中随机抽取一份礼物进行准备。

进入“为TA抽选”
→
设置最高预算 (选填)
→
点击盲盒抽选
→
抽中并揭晓结果
→
「就选它了」或「再抽一次」

抽选算法与业务规则：

  • 优先级权重：高优先级心愿赋予更高抽中概率（加权算法：高权重 5、中权重 2、低权重 1）；同优先级同概率随机抽取；
  • 预算筛选规则：填写预算后，仅抽取标有明确价格且不超过预算的心愿；价格未知的心愿不参与设置了预算的抽选；不填预算则全部心愿参与；
  • 连续重抽排除机制：
    • 点击「就选它了」：锁定该心愿，心愿进入送礼者的进行中任务，不再重复被抽；
    • 点击「再抽一次」：立即自动触发下一次抽选，并且在本次抽选会话中严格排除刚刚抽中的物品，防止连续抽到同一件；
  • 防重复锁定：已被当前送礼关系抽中的心愿立即进入锁定状态，不可再次抽取；
  • 逾期过滤：截止日期已过的心愿自动不参与新的抽选。

5.6 送礼进度管理（全流程保密）

状态流转：

已抽中 (锁定心愿)
→
已购买 (记录凭证备忘)
→
已送出 (揭晓心意)

保密与体验要求：

  • 抽选过程、抽中状态及购买备注全程对心愿主人严格保密；心愿主人在查看自己清单时完全看不到剧透；
  • 只有当送礼方在线下亲手送出礼物后，在 App 中点击「确认已送出！」，系统才会触发全屏庆祝礼花，正式向收礼方发送惊喜通知并揭晓送礼者；
  • 中途取消机制：送礼方可在任何阶段放弃送礼任务（二次确认）。放弃后心愿立即解锁重回候选池，系统不会向心愿主人发送取消通知，最大程度保护隐私与期待。

5.7 礼物历史记录

送礼完成后，记录自动归档至「送礼历史」，形成情侣专属的甜蜜回忆册：

  • 我收到的礼物：查看收到的心愿物品、揭晓的送礼方、送达时间以及对方留下的暖心备忘；
  • 我送出的心意：查看自己送给另一半的礼物历史足迹。

5.8 站内通知系统

包含四大核心站内通知类型：

  • 情侣绑定通知：收到绑定邀请、邀请被接受/拒绝；
  • 送礼惊喜通知：另一半确认送出礼物后的惊喜揭晓与祝福；
  • 心愿变动通知：若主人删除了已被抽中的心愿，系统自动终止送礼任务并通知送礼方；
  • 关系变动通知：情侣关系解除提醒。

5.9 心动纪念日与节日备忘（恋爱纪念日、生日、情人节等）

功能说明：情侣送礼高度依赖节点触发（相恋周年、双方生日、情人节、圣诞节等）。应用提供仪式感十足的纪念日管理与倒数备忘功能，将「纪念日倒数」与「心愿抽选」深度联动。

  • 预设情侣关键节点：支持一键快捷设定恋爱纪念日（在一起的第一天）、TA的生日、我的生日、西洋情人节 (2.14)、520 告白日、七夕情人节、圣诞节 (12.25) 及自定义纪念日；
  • 相恋天数与倒数日自动计算：
    • 恋爱天数累计：自动计算相伴总天数（例如“相恋第 876 天”），直观呈现长情岁月；
    • 周期性节日倒数：每年自动循环计算下一个纪念日剩余天数（例如“阿澈的生日 还有 24 天”）；
  • 提前送礼备忘提醒：支持自定义提前提醒天数（提前3天、7天、15天、30天），在首页与抽选送礼页面显著展示备礼提醒；
  • 送礼抽选无缝联动：倒数日卡片直接附带「为TA备礼 / 抽选心愿」入口，一键直达抽选流程，解决节日将至不知道挑什么礼物的核心痛点。

六、V1.0 暂不做功能（严控 MVP 范围）

为确保 V1.0 能够快速验证情侣核心闭环，以下功能明确不纳入本次开发范围：
  • ❌ 多人绑定（V1.0 仅限一对一情侣）；
  • ❌ 朋友/家人等多重复杂关系；
  • ❌ 外部公开分享链接与网页游客查看；
  • ❌ 分组权限体系；
  • ❌ 独立避雷清单（简化由心愿备注表达）；
  • ❌ AI 礼物算法推荐；
  • ❌ 电商内置商城与自动下单；
  • ❌ 在线支付与红包转账功能；
  • ❌ 公开社区与社交动态广场。

七、页面结构设计

移动端优先，底部主导航设置四个核心主入口，通知信息精简移至页面右上角铃铛，以实时角标形式呈现：

入口 页面名称 核心呈现内容与操作
顶部右上角 消息通知铃铛 未读红点/数字角标呈现，点击滑出通知浮层，查看情侣绑定邀请、送礼揭晓提醒与心愿变动通知
Tab 1 首页 (Home) 情侣绑定天数与状态卡片、我的心愿数量统计、待完成送礼任务速览、快捷入口（记心愿、为TA抽选）
Tab 2 心愿清单 (Wishes) 顶部分段控制（【我的心愿】⇋【TA的心愿】）、视图模式切换、分类与优先级过滤、心愿增删改查、清单一键暂停
Tab 3 为TA送礼 (Gift Draw) “为TA送礼”抽选控制台、最高预算筛选、盲盒动态抽选动画、结果弹窗（就选它了 / 再抽一次）、正在准备的送礼任务列表
Tab 4 我的 (Profile) 头像昵称资料修改、情侣关系管理、送礼历史回顾、账号与隐私设置、原型多视角切换器

八、核心用户流程

流程 1：创建心愿流程

打开 App
→
进入「心愿」页面
→
点击「+ 记心愿」
→
填写标题、价格、规格、优先级
→
保存入库
→
另一半随时在TA的心愿中可见

流程 2：惊喜送礼抽选与履约流程

进入「抽选」页
→
选择设置最高预算
→
点击「开始随机抽选！」
→
抽中礼物结果弹窗
→
点击「就选它了」锁定
→
线下采购后标记「已购买」
→
纪念日当面送出并「确认已送出」
→
全屏礼花揭晓，沉淀至历史

九、原型验收标准（Definition of Done）

第一版 MVP 原型验收清单（全部已验证）：
  • ✅ 用户能够正常新增、编辑和删除心愿，并支持设置价格、规格、多图片和优先级；
  • ✅ 支持情侣 1 对 1 绑定与解绑流程，解绑后未完成的送礼流程立即安全终止；
  • ✅ 在「心愿」页面可自如切换查看「我的心愿」与「TA的心愿」；
  • ✅ 送礼方可设置最高预算，系统仅匹配标价且不超标的心愿；
  • ✅ 抽选弹窗提供「就选它了」与「再抽一次」；点击再抽一次直接触发下一轮并排除刚抽中物品；
  • ✅ 抽中与购买状态对心愿主人严格保密，送出瞬间触发庆祝仪式与揭晓通知；
  • ✅ 双方均可在「送礼历史」中查阅完成的历史记录；
  • ✅ 支持顶部切换「小桃」与「阿澈」视角，无缝体验双方的秘密互动与通知反馈。
